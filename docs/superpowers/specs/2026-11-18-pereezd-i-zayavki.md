## Что делаем

### 1. Приёмник заявок

PHP-скрипт на хостинге клиента. Порядок работы:

1. Принимает POST с полями и файлами
2. Проверяет: ловушка `website` пуста, согласие дано, обязательные поля заполнены, типы файлов из белого списка (JPEG/PNG/WEBP/PDF), суммарный размер в лимите
3. Собирает письмо: тема «Заявка с сайта — <Имя>», тело с полями, **файлы вложениями**
4. `Reply-To` = контакт посетителя, чтобы отвечать прямо из письма
5. Отправляет **через SMTP ящика на Яндексе с авторизацией** — не через `mail()`, иначе спам
6. Пишет копию в журнал на сервере (дата, поля, имена файлов) на случай сбоя почты
7. Возвращает JSON; на странице показывается «Заявка отправлена»

На фронте: вписать адрес приёмника в `data-endpoint`. Больше в вёрстке ничего не меняется.

**Запасной путь для больших пакетов:** если суммарный размер выше лимита хостинга — файлы остаются на сервере, в письме ссылка на скачивание.

### 2. Переезд на хостинг nic.ru

1. Сохранить копию старого сайта
2. Залить новый во временную папку, проверить по технической ссылке
3. Поменять местами: старый в архив, новый в корень
4. DNS **не трогать** — домен уже указывает на этот сервер
5. Проверить: сайт, замочек, почта, `?edit`

### 3. Админка: публикация по FTP вместо GitHub

Переписать `galars-publish` так, чтобы она клала изменённые файлы прямо на хостинг, а не коммитила в GitHub. GitHub остаётся архивом исходников и историей.

### 4. Починить SPF и добавить DMARC

Убрать `ip4:IP-1 ip4:IP-2 ip4:IP-3`. Добавить DMARC в мягком режиме. Влияет на доставляемость всей почты компании.

### 5. www и сертификат

Добиться, чтобы `www.galars.ru` открывался по HTTPS. Сейчас сертификат его не покрывает.
